# 🔖 佳文摘录

读到值得回看的文章，就在这里留一份：原文关键内容 + 出处 + 我的简评。方便以后回看，也省得重新搜。

每条都写清出处链接，不代替原文。新摘录按四段写：引文 + 出处 + 为什么摘 + 我的用法。

## 《The Grug Brained Developer》

> apex predator of grug is complexity
> complexity bad
>
> best weapon against complexity spirit demon is magic word: no

**出处**：[The Grug Brained Developer](https://grugbrain.dev/)、Carson Gross

**为什么摘它**：用穴居人语气讲透一件事：复杂度是软件的头号敌人，而最有力的武器是说「不」。每次想加「以防万一」的代码时，都会想起这篇。

**我的用法**：评审自己的设计先问「这个能不能不加」，确认必须加再谈怎么加。博客导航收敛也是同一逻辑。

## 《Maker's Schedule, Manager's Schedule》

> A single meeting can blow a whole afternoon, by breaking it into two pieces each too small to do anything hard in.

**出处**：[Maker's Schedule, Manager's Schedule](https://paulgraham.com/makersschedule.html)、Paul Graham

**为什么摘它**：解释了为什么「半小时的会」对写代码的人是灾难：被切掉的不是半小时，是整个下午的整块时间。

**我的用法**：把会议和沟通集中到固定时段，保住整块时间写东西、调问题；和 AI 协作也一样，先一次对齐方案，再让它完整跑完。
