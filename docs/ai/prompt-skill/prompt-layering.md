# 🧩 Prompt 的结构化写法与分层复用

「一句话魔法」用两次就失效：换个任务要重写，换个工具要重抄。把提示词当资产的第一步，是分层。

## 一条提示词拆成四层

- **约束层**：角色、语气、禁止事项。最稳定。
- **任务层**：这次要做什么。每次变。
- **上下文层**：文件、数据、背景。每次变。
- **输出层**：格式、长度、验收标准。半稳定。

写的时候按这四层各占一段，别混成一大段散文。混在一起，改一处就要重读全文。

## 稳定层沉淀出去，会话里只留变的

约束层里每次都要的部分，进 Rules / 约定文件（比如仓库里的 AGENTS.md）；重复三次以上的流程，做成 Skill。会话里只留本次的任务和上下文。

这样同一条约束只写一遍。抄来抄去的提示词会产生分叉：三份拷贝各自演化，最后没人知道哪份是对的。

## 输出层要带验收标准

「输出表格，含出处链接，不超过 5 行」比「写得好一点」稳定得多。验收标准尽量机器可查：格式、字段、长度。查不了的，才留给人看。

## 复用靠引用，不靠复制

稳定层放进单一文件，各工具引用同一份，用 [Quiver](/vibe-coding/quiver) 这类工具做多端分发。改的时候改一处，所有端下次同步就生效。

分层的本质就一句话：**把变的和不变的分开**。不变的沉淀成资产，变的留在会话里。
