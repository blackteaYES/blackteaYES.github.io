# 🔁 从需求到部署：一条 AI 辅助流水线跑通记

拿博客导航重构当例子，记录一次「人定方向、AI 执行、流水线验收」的完整流程。

## 第一步：只读分析，不动文件

先让 Agent 盘点现状：导航几栏、哪些目录空、哪些链接死。这一步明确禁止改文件。分析和动手混在一起，是返工的主要来源。

## 第二步：对齐方案再动手

分析产出方案，人确认边界：哪个目录不启用、哪些路径不许改、哪些内容合并。边界定了，Agent 才开工。

## 第三步：构建即验收

每批改完跑 `npm run build`，构建不过一切免谈。UI 改动还要开浏览器点一遍导航和新页面——构建通过只证明代码对，不证明功能对。

## 第四步：提交按性质拆

栏目页、专题页、标签、导航、文档各成一笔；混在同一文件里的就合并。拆分的好处不是好看：出问题时能精确回退。

## 第五步：推送后交给流水线

推 main，GitHub Actions 自动构建部署（见 [自动部署实验](/projects/demos/github-actions-deploy)）。人不手动传产物，流水线保证「仓库里是什么，站上就是什么」。

## 复盘

这条流水线里，人的价值集中在两端：定边界、验结果。中间的执行交给 Agent，验收的标准交给构建和部署。**交出去的是执行，不是判断。**
