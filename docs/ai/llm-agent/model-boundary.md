# 🧭 什么交给模型，什么写死代码

用了一阵子编码 Agent 之后，我被问最多的问题是：这东西到底能信到什么程度？我的答案不是程度，是分工。

## 一条判断标准：输出能不能验收

如果一个任务的输出能被机器验收——测试通过、编译成功、金额对账——那就放心让模型做，验收交给代码。如果输出只能「看一眼」，比如措辞、文风，那就让模型出草稿，人来定稿。

最怕的是中间那种：看起来能验收，实际上没人验收。

## 必须写死的三类逻辑

- **金额与计数**：计费、库存、分页总数。模型的「差不多对」在这里行不通。
- **权限与边界**：谁能看什么、谁能改什么。写进代码，别问模型。
- **状态流转**：订单状态、重试次数。状态机比任何提示词都可靠。

## 适合交给模型的三类任务

- **总结与抽取**：长文档抓重点、日志里提字段。
- **分类与打标**：目录归类、文章打标签。错了成本低，重跑就是。
- **草稿生成**：代码初版、文章初稿。价值在于给起点，不是给定稿。

## 中间地带：模型出草稿，代码做验收

[dir-content-analyzer](/vibe-coding/dir-content-analyzer) 就是这么划线的：目录体积、文件数量由传统扫描算出来，一个字节都不交给模型；LLM 只做语义分类和清理建议，建议错了也不影响扫描结果。

**模型负责模糊的一半，代码负责确定的一半**——这个分工比争论「哪个模型更强」稳定得多。
